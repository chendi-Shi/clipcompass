# 面试讲解：真实日志上的内容冷启动推荐

## 三分钟讲清楚

1. **问题**：新内容没有协同交互，纯ID推荐缺少可用信号。我研究内容语义与协同图的融合，以及它对整体排序的影响。KuaiRec观看偏好只是用户兴趣代理，不能等同创作意图。
2. **数据**：读取467.7万条真实曝光，首次曝光去重后449.5万条；按全局时间划分。314个内容的训练行为全部隐藏，内容标题仍可用。训练正例是watch_ratio≥2，负例是已曝光且watch_ratio<1。
3. **模型**：两层LightGCN仅用训练正例构图；冻结E5提取标题/封面文字语义，学习语义投影和用户正例历史画像。门控融合协同与内容分支，cold内容完全依靠内容分支。BPR优化同用户曝光排序，InfoNCE检查图/语义对齐是否有效。
4. **证据**：EASE、MF、LightGCN、文本画像等9种方法；神经模型3seed，验证选checkpoint。打开REAL_REPORT.md，分别解释warm、cold和混合候选指标，再给出逐用户配对bootstrap。数值以报告为准，不以测试涨幅选模型。
5. **扩展**：实际训练Qwen0.5B最后4层q/v LoRA做8类文本分类，比较base prompt、TF-IDF/E5线性分类器。冻结前缀缓存先校验logits一致与LoRA梯度，再训练。该实验没有作为推荐模型输入，因此不能归因推荐收益于LLM微调。

## 高概率追问

**为什么没有视频也叫短视频推荐？** 推荐对象是真实短视频，输入特征是其标题与封面文字。准确名称是“内容语义增强的短视频推荐”，不是“视频多模态理解”。真实视觉特征需要另行获取视频并实验。

**为什么LightGCN适合？** 用户与内容的二部图提供协同信号，线性归一化聚合是清晰可复现的图基线。不能把测试边加入图。EASE与MF用于防止只对比弱热门基线。

**冷内容有没有偷偷使用行为？** SHA256对原始video_id做固定约10%划分；全部cold训练标签移除，其验证标签也不参与选择。ID分支强制屏蔽；推理只用语义。预训练编码器可能有外部语料记忆，不能证明内容从未被预训练模型见过。

**为什么取首次曝光？** 重复曝光如果用后续最大观看比聚合，会把未来标签放入早期事件。首次时间与首次行为一起保留，代价是舍弃重复消费信息。

**为什么不随机采样负例？** 数据提供真实曝光，未曝光不代表负反馈。训练只采同用户已曝光的正负对；评测排序所有该用户测试期观察到的曝光内容。这个回顾性协议仍有曝光策略偏差，不是线上候选生成或因果评测。

**冷组提升很大就说明成功吗？** 冷组目录较小，Recall@20天然更高，不能与warm数值直接比较。纯ID冷分支分数相同，打破平分依赖固定ID；还需对比E5内容基线，并检查warm/cold混排是否出现分数尺度问题。只写冷组涨幅会掩盖整体退化。

**对比学习为什么可能退化？** 图/文本对齐目标不必与用户偏好一致，批内同主题内容也可能是假负例。固定SSL权重的消融结果只说明这一配置，不能推广为对比学习无效。未根据测试结果修改权重。

**LoRA优化了什么？** 输入类别代码表与标题，回复一个类别token；在完整词表上算该回复位置的交叉熵。不是只在8类softmax上训练，也不是开放式生成SFT。测试类别预测在固定代码集内取最大值，另报告不约束时首token合法率。

**为什么缓存不会改变训练？** 冻结的前20层和固定公共prompt计算不依赖最后4层LoRA参数；因果注意力使公共prompt不依赖后续标题。缓存FP32隐藏状态和KV，先与完整模型logits做容差检查；小模型测试同时检查右侧padding、shared KV和LoRA梯度。它节省计算，但本项目没有独立计时对照，不能写速度提升百分比。

**LoRA不如线性分类器怎么办？** 照实报告。微调实现正确不代表最适合任务，尤其小标注预算、噪声类别、少量更新时。分类器用同一独立标注预算，C由验证集选择；若胜出，工程选型优先考虑更简单的方法。

**CPU延迟能说明什么？** 只说明3327内容目录下，加载后的向量评分、曝光过滤、topk和JSON构建的时延。不含HTTP、E5编码或模型加载，也不是百万级召回压测；并发训练会影响本机测量，报告测量条件。

## 不能写成已完成成果

百语种迁移、原始视频理解、MLLM微调、7B训练、线上CTR/A-B提升、创作者灵感采纳率、连续预训练、LLM蒸馏。目前这些没有对应实验。旧合成RGB/蒸馏demo不作为真实研究成果。

后续研究应针对实际结果选择方向：内容/协同分支校准、独立验证SSL权重、真实视频特征、作者侧创作意图标签。任何新方法都需要新的验证/测试方案，避免反复看同一测试集调参。
